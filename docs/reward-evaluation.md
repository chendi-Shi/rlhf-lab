# 奖励模型的独立评估

`score_reward(config, model_path, split="valid", output_path=None, limit=None)` 对已完成训练的奖励模型做真实 GPU 推理，比较同一文章的 chosen 与 rejected 分数。默认只评估 valid；最终 test 需要显式指定，避免反复用测试结果调参。

接口要求匹配的奖励模型检查点、真实人工偏好数据来源、有效数据哈希，以及空闲显卡和匹配的依赖版本。资源检查之前不会导入 Torch。不会覆盖已有结果文件。`limit=None` 使用配置中的 `eval_limit`，按准备好的确定性顺序取前 N 对。

每个比较分别推理两个摘要，输出成对准确率、`-log(sigmoid(chosen_score-rejected_score))` 损失、相等分数数量及文章宏平均准确率/损失。文章宏平均先在每篇文章内部平均，再给每篇文章相同权重，避免多比较文章主导结果。分数完全相同按严格准确率计为错误。截断后完全相同的两个摘要不计入指标，剔除条数会明确记录。

结果文件默认位于运行目录的 `evaluations/reward_valid.json` 或 `reward_test.json`，包含实际分数、样本量、截断剔除量、来源与模型清单 SHA-256、运行配置和实际耗时。该指标衡量奖励模型与人类比较标签的一致性，不能替代生成摘要的人工盲评，也不能直接证明 PPO 改善质量。

目前只验证了纯 Python 保护逻辑和数值汇总测试，尚未执行奖励模型推理，没有真实评估结果。
