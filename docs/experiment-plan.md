# 实验计划与验收标准

本文件为执行前计划。所有结果字段均待真实训练、测量与人工评审后填写。

数据准备已完成：从官方 train 前 3,000 条偏好比较构建本地试跑划分，偏好对为 1,024/128/128，不同原文为 268/34/33（train/valid/test）。SFT 样本为 686/88，PPO 为 268 个提示词，最终评估原文有 33 个。完整性校验已通过。这些是数据统计，不是模型效果；本地 valid/test 不是官方 valid/test。

## 研究问题

在单张 8GB 显存显卡上，小型英文摘要模型完成 SFT、人类偏好奖励建模及 PPO 后，质量、资源成本与稳定性如何变化？主要对照是相同 SFT 起点下的 SFT 与 PPO；Base 用于解释监督训练的贡献。

主要假设：适度的 KL 约束能在优化偏好奖励时限制输出退化。结果可以是不改善或退化，应保留证据并解释原因。小模型上的结论不能直接推广到更大的模型。

## 数据与隔离

使用公开 `CarperAI/openai_summarize_comparisons` 的人工偏好比较。记录来源、下载日期、revision（可获得时）、原始分区、清洗规则、过滤数、最终样本数、提示词规范化方法和本地文件摘要值。样本公开展示时保留出处，遵守原数据使用条件，不声称拥有原始文本。

当前原始文件约 5.15MB，附逐行哈希和分页请求记录。下载前后仓库 SHA 与每页 `x-revision` 均为 `a320fae2cd84f04610a1b57ac83c2a2f674b8bcd`；读取的是非版本化 rows API 的已核验快照，不宣称 URL 本身锁定返回字节。只取官方 train 的有序前缀，存在采样偏差。正式扩大数据时重新记录数据方案，不把当前本地测试结论混同于官方测试集结果。

按规范化后的提示词分组划分 train/validation/test，保证同一原文的多组比较始终属于同一分区。SFT、奖励模型训练和 PPO 仅使用 train；validation 用于选超参数；test 最终使用一次。不同偏好配对共享同一原文时，统计有效测试提示词数，避免把相关配对当成完全独立的观察值。

SFT 使用 train 中的人类优选摘要，是偏好数据导出的监督目标；这和原论文独立收集的示范数据不同，需在报告中明确。优选摘要也可能存在事实错误和噪声，准备后先人工抽查 20–30 组。

pilot 优先验证代码。其数据规模与采样范围不代表正式训练分布。正式运行前固定分区，并检查长短文本、主题、重复率和截断比例；不能靠反复查看 test 选择模型。

所有阶段共用 `原文 + \n\nTL;DR:` 的提示格式，并去除监督/偏好摘要已有的前导 `TL;DR:`。pilot 提示预算 192 token，回答预算 64 token；提示词保留末尾，长原文的较早部分会被截断。记录输入截断比例，检查训练目标是否要求模型总结它看不到的内容，并将这一限制纳入失败分析。

## 首轮试跑

1. 手动安装环境，记录 OS、Python、全部依赖、GPU 和驱动版本；检查驱动与 CUDA wheel 的实际兼容性。
2. 运行资源检查，确认 GPU 可用。保留当前配置，不与其他模型进程争用资源。
3. 抽查输入、摘要边界与 EOS；检查 SFT 的损失只覆盖应训练的目标 token，检查 RM 的 chosen/rejected 次序。
4. 跑 pilot 三阶段。SFT/RM 记录每步耗时，PPO 记录 episode 数、生成 token 数和耗时；三者单位不能直接混用。
5. 确认产生可重新加载的 checkpoint。比较初始/最终参数或检查点摘要，确认发生优化更新；仅有损失打印不能作为充分证据。
6. 检查损失有限、生成不全为空、不全部重复；复查 PPO 确实读取本次 SFT/RM 产物和固定参考策略。
7. 从预热后的一段记录估计整体成本：`预计耗时 ≈ 剩余训练单位 × 实测平均单元耗时 + 评估/保存开销`。另报下载、环境适配与等待 GPU 的时间。

保留峰值显存（包括 allocated/reserved 的统计口径）、可用主机内存、吞吐量、最大输入长度、最大生成长度、批量大小、梯度累积、数值精度。通过资源门槛不代表显存预算已经验证。

## 基线与实验顺序

| 实验 | 起点 | 目的 | 执行条件 |
|---|---|---|---|
| Base | GPT-2 124M | 预训练模型摘要基线 | 固定留出提示词与生成配置 |
| SFT | Base | 验证监督训练贡献 | pilot 通过后扩大数据/步数 |
| RM | SFT 主干与新评分头 | 学习人类偏好 | validation 偏好判断稳定优于随机后再研究 PPO |
| PPO 默认 | 同一份 SFT，固定 RM | 完整闭环 | 两个上游模型已保存并检查 |
| PPO 较低 KL | 同一份 SFT，固定 RM | 检查激进更新与奖励利用 | 默认 PPO 已能稳定运行 |
| PPO 较高 KL | 同一份 SFT，固定 RM | 检查约束过强导致学习不足 | 与其他 PPO 组相同预算 |

先比较三档 KL，例如默认值的 0.5 倍、1 倍和 2 倍。每次只改变一个主要变量，并使用不同配置文件和输出目录。资源允许再选两个数据量或两到三个随机种子，不必一次铺开大矩阵。所有实验共用固定 test；调参过程只使用 validation。

## 指标与解释

| 阶段 | 必须记录 | 解释限制 |
|---|---|---|
| SFT | 训练/验证损失、样本输出、token 长度、耗时、显存 | 损失下降不等于事实性提高 |
| RM | 留出偏好准确率、chosen/rejected 分差、样本数 | 检查长度偏好和噪声；准确率不是摘要质量 |
| PPO | 策略奖励、KL、策略/价值损失、clip fraction、生成长度、EOS、重复率 | 单看 RM 奖励可能掩盖 reward hacking |
| 最终评估 | 匿名人工胜/负/平局、事实错误、覆盖度、重复/空输出、资源成本 | 报告规则、样本量与区间；不能仅展示最好案例 |

TRL 记录的指标名称和含义以 [0.25.1 PPO 文档](https://huggingface.co/docs/trl/v0.25.1/en/ppo_trainer)为准。跨不同奖励模型的原始奖励分数不能直接比较。

## 盲评规则

先在 validation 上用 20–30 个原文试评并统一标准。当前 pilot 仅有 33 个不同 test 原文，默认生成其中 32 条，仅作流程验证。正式实验扩大数据后，尽量抽取至少 100 个独立 test 原文；预算不足时如实报告较小样本，不预设显著提升。每个模型使用相同原文与固定的生成参数，随机交换 A/B 位置，评审材料隐藏模型名与训练阶段。

判断优先级：

1. **忠实性**：是否编造原文没有的信息、人物关系或结论。
2. **覆盖度**：是否保留原文主要事件和结果。
3. **简洁与可读性**：是否有无关内容、机械重复和明显断句问题。

选择 A、B 或平局，必要时标记无法判断，并简述原因。模型映射和评审表分开保存；完成判断后再解盲。可以邀请第二名评审者复核一部分样本，报告分歧及解决规则。

报告至少包括：A/B 胜负数、平局数、未判定数和实际比较数。若用“半平局计分”，写明 `(胜 + 0.5 × 平局) / 有效比较数`；若用排除平局胜率，也同时报告被排除的平局比例。不同口径不能混用。二项区间用于胜/负这种二元观察值，不能把半平局后的分数直接当成二项成功次数；保留逐条判断，以便按提示词 bootstrap 估计不确定性。

奖励模型的 held-out 准确率与人工摘要胜率分别报告。人工评价者可以是本人，但应明确披露；“用了人工偏好公开数据”不等于“自己采集了人类反馈”。

## 失败案例与停止条件

至少保留改进、无变化、退化三类案例，按固定抽样规则选择，不只展示好结果。重点排查长输出获取更高奖励、重复文本、无 EOS、忽略原文和短摘要丢失关键信息。

遇到 OOM、NaN、持续空输出、KL 异常增长或奖励提高但人工质量下降，暂停扩大实验，记录当时配置与日志。先缩短序列、减小批量、检查 mask/边界及模型衔接，再决定是否调整学习率或 KL。资源问题和算法效果问题分开记录。
